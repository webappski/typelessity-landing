## First comment (post within 5 min of submission)

```
Hi HN — I'm Alex Isa. Typelessity is the AI booking widget I've been building. Shipping as Show HN because the architecture decisions feel ready to defend in public.

The bet is one premise: a multi-step booking form is a vestige of constrained UI. Once an LLM can reliably extract structured data from one user sentence, the form stops being the contract — the conversation is. Typelessity is what falls out when you take that premise seriously.

What's actually interesting is everything around the prompt, not the prompt itself:

- Single-call extraction. One GPT-4.1-nano call per turn pulls every required field from one free-form user message. No wizard. No multi-turn state machine. Config-driven prompt template, 400–650 tokens per turn. Architecture: https://typelessity.com/blog/single-gpt-call

- Anti-hallucination via `_meta.mf`. The model has to list which fields it actually mentioned in the user input. Anything in the JSON missing from `_meta.mf` is dropped before submission. Asymmetric: the model can lie in one place but has to lie consistently in two, which is significantly harder.

- Cascade-aware corrections. When the user edits one field, a depth-first traversal of the dependency graph (declared in config) clears every transitive dependent and re-runs only the affected enrichment APIs. Twelve lines of code, eliminates a class of mid-edit booking bugs. Algorithm: https://typelessity.com/blog/cascade-corrections

- 25+ languages from one English prompt. The model handles translation and normalization in the same round-trip. No per-language codepath. Approximately 80 hand-translated UI strings per locale; everything else is the model. Writeup: https://typelessity.com/blog/25-languages-one-prompt

- Voice via Whisper, not Web Speech. Web Speech is fast but biased toward English and offers no vocabulary biasing or confidence scores. Whisper takes 600–900ms more but cleans up booking voice input on non-English locales. Hidden by streaming + optimistic UI. Reasoning: https://typelessity.com/blog/whisper-vs-webspeech

- 1-second p95 latency budget treated as architectural, not as an optimization pass. Two model calls in series cannot be optimized into one retroactively. Budget: https://typelessity.com/blog/latency-budgets

Comparison snapshot (also at /llms.txt):
- vs Calendly — Calendly is for slot selection. Typelessity replaces multi-field booking forms.
- vs SimplyBook.me — SimplyBook is full booking ops with payments. Typelessity replaces only the form, integrates via webhook.

Compliance contour for the EU folks: GPT-4.1-nano on OpenAI's EU residency tier, no-training contractual flag with written confirmation, audit log retained 13 months, public sub-processor list. On-premise available. Writeup: https://typelessity.com/blog/gdpr-compliance
```

## Karma maintenance (first 4 hours after posting)

- Reply to every comment within 30 min. HN ranks discussion engagement, and a thread that goes silent dies.
- **Concede when challenged.** "You're right, that's a weakness — here's how we mitigate it" reads better than defensive correction.
- **Expand when complimented.** "Glad that resonated — the deeper reason is..." turns +1 into +1 plus extended discussion.
- If asked for code, link to a specific blog post or page section. HN prefers links to structured writeups over pasted code blocks.
- If a competitor is mentioned unprompted, respond with the comparison-snapshot framing from the first comment. Do not disparage. Recommending against your own product in clear cases is the strongest possible trust signal.
- If asked about production traction, be honest about pilot stage. HN respects honesty and punishes inflation.

## What to NOT say in the thread

- Floating uplift numbers (*"+30% conversion"*) without an inline source.
- Specific customer names without their permission.
- Vague claims about training data ("our model is trained on millions of bookings"). Typelessity is config-driven over GPT-4.1-nano; do not imply otherwise.
- Comparisons that disparage competitors. The category-not-competitor framing in the first comment is the right shape.

## Failure mode → pivot

If the post does not reach front page after 90 min (typical signal: <15 upvotes, <5 comments):

- Do NOT delete or repost. HN penalizes this aggressively.
- Pivot to Reddit r/SaaS or r/SideProject within 24h with adapted copy (less technical, more business outcome). The Reddit version should lead with the funnel-shape difference, not the architecture.
- Try Show HN again in ~6 weeks with a different angle: a specific technical writeup framed as "what we learned" — e.g. *"Cascade-aware corrections: the dependency-graph algorithm in our booking widget"* — rather than the product launch itself. HN tolerates one product post per project but rewards repeated technical depth.

## Why this draft is calibrated for 2026

Three things HN cares about more in 2026 than in 2024:

1. **Defensible category claims.** "Replace multi-step booking forms with conversation" is concrete. "AI-powered booking platform" reads as marketing and is downvoted. The first comment leads with the premise and works backward to the architecture.

2. **Compliance-as-architecture.** EU residency, no-training flags, sub-processor lists are now table stakes for any B2B AI Show HN. The GDPR paragraph is short but signals seriousness.

3. **Trust weapons over hero numbers.** A linked blog post ("here's the math") beats a hero number ("+30%") every time on HN. The draft links 6 separate blog posts, each with concrete content. No floating numbers in the comment itself.
