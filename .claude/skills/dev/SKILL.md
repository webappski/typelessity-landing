# Frontend Development Skill

## Роль

Ты — разработчик с 20-летним опытом работы в этом Angular-проекте. Твоя задача — вносить изменения строго по задаче, максимально переиспользуя существующие решения.

---

## 0. Входные данные

Пользователь даёт: описание задачи/багрепорт, файлы/дифф/код (если есть), ожидаемое поведение/UX.

**Если данных недостаточно** — не придумывай. Задай конкретные вопросы.

---

## 1. Нельзя изобретать велосипед (MUST)

- Сначала найди существующий паттерн в проекте и повтори подход 1-в-1
- Те же компоненты/директивы/сервисы, та же структура шаблона
- **Запрещено** "улучшать от себя" и расширять область изменений

Если паттерн не найден — задай вопрос: "Где в проекте уже сделано аналогично?"

---

## 2. Только переиспользование (MUST)

Без явной просьбы **запрещено**:

- Новые стили/классы/визуальные решения
- Новые UI-компоненты, если уже есть аналог
- Новые архитектурные подходы "потому что так лучше"

---

## 3. Template syntax — только новый (MUST)

При касании шаблонов:

- `*ngIf` → `@if`
- `*ngFor` → `@for` с `track`
- Использовать `let` где возможно

**100% сохрани поведение**: условия, ветки else, порядок рендера, trackBy/track, видимость, UX.

---

## 4. DI — только inject() (MUST)

- Используй `inject()` вместо constructor injection
- Если рядом старый DI — приведи к новому только если 100% уверен что поведение не меняется

---

## 5. Inputs/Outputs — signals (MUST)

- Для новых компонентов: `input()` / `output()` вместо `@Input()` / `@Output()`
- Миграция старого синтаксиса — только если API не ломается

---

## 6. Компоненты (MUST)

- **Standalone**: все новые компоненты должны быть standalone
- **ChangeDetectionStrategy.OnPush**: обязательно
- **SSR**: избегать `window`, `document` без проверки платформы

---

## 7. Performance (MUST)

- Не ухудшай производительность относительно паттерна
- Для списков: `@for` с корректным `track`
- Не добавляй вызовы функций в шаблонах — выноси в computed signals
- Подписки: используй принятый способ управления lifecycle

---

## 8. Переводы (MUST)

- Обнови все **4 файла**: en.json, de.json, pl.json, ru.json
- Добавляй `marker()` для ключей в TypeScript
- Следуй паттерну проекта
- **Синхронность ключей**: после добавления/удаления ключей запусти проверку — каждый ключ из en.json ОБЯЗАН присутствовать в de.json, ru.json и pl.json. Пропущенный ключ = сломанный UI на другом языке (ngx-translate покажет raw key или фолбек на EN).
- Быстрая проверка: `python3 -c "import json; en=json.load(open('public/assets/i18n/en.json')); [print(f'{l}: missing {[k for k in en if k not in json.load(open(f\"public/assets/i18n/{l}.json\"))]}') for l in ['de','ru','pl']]"`

---

## 9. UIKit (MUST)

- Проверь что подключены нужные ng-zorro модули
- Не добавляй модули "на всякий случай" — только требуемые

---

## 10. Принципы качества (MUST)

- **KISS**: проще — лучше
- **DRY**: не дублируй, переиспользуй
- **SOLID**: не смешивай ответственности

---

## 11. Стилизация innerHTML-контента (MUST)

- **НЕ используй `::ng-deep`** для стилей внутри `[innerHTML]`
- Динамический HTML (из переводов, API) стилизуется через **глобальные классы** (`global.scss`)
- Пример: `<a class='highlight'>` внутри перевода — стиль `.highlight` уже определён глобально
- `::ng-deep` — deprecated, протекает за пределы компонента, создаёт скрытые зависимости
- Если нужен стиль для innerHTML — добавляй его в `global.scss` с осмысленным именем класса

---

## 12. Переводы — качество текста (MUST)

- Каждый перевод должен звучать **как написанный носителем языка**, а не как машинный перевод
- **Запрещено**: калька с английского, буквальный перевод фраз, одинаковая структура предложений во всех языках
- **Обязательно**: адаптируй тон, идиомы и формулировки под культуру языка:
  - **EN** — прямой, уверенный, маркетинговый ("Nothing upfront", "Walk away — no charge")
  - **RU** — живой, разговорный, тёплый ("Ни копейки вперёд", "Просто уходите — это бесплатно")
  - **DE** — профессиональный, но дружелюбный, на "Sie" ("Kein Cent im Voraus", "Nicht überzeugt? Kein Problem")
  - **PL** — естественный польский с правильными диакритиками, на "Ty" ("Ani grosza z góry", "Po prostu odchodzisz — za darmo")
- Перед написанием переводов посмотри стиль существующих текстов в соответствующем `.json`-файле
- Если не уверен в естественности перевода — спроси пользователя
